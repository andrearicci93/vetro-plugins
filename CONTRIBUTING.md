# Contributing a plugin

Read [what a plugin can and cannot do](docs/what-a-plugin-can-do.md) and the [guide](docs/writing-a-plugin.md) first.

## What a pull request contains

- the source in `plugins/<id>/` (`manifest.json`, the entry file, a short `README.md`); start from `node scripts/new.cjs <id>`;
- `dist/<id>-<version>.vplugin` and `index.json`, generated by `node scripts/build.cjs`. CI runs
  `node scripts/build.cjs --check` and fails when a plugin breaks a rule below that a machine can check, or when they
  are out of date;
- a new `version` for every change to an existing plugin. The hash in `index.json` must always describe a
  published version, so a changed bundle with the same version is refused (CI compares with `main`).

Only the maintainer signs `index.json`; do not add a `signature` yourself.

## What the maintainer checks

- The code is readable: no minified or obfuscated source, no `eval` or `new Function`, no downloaded code.
- It talks only to what the description says. No network calls to hosts the description does not mention, no
  collection of data about the user, the TV or the network.
- `permissions` is as small as possible. A plugin that asks for `exec` must say in its README which commands it
  runs and why; a plugin that does not need `exec` must not ask for it.
- It cleans up in `stop()` (timers, sockets) and keeps its own data in its folder or in `ctx.config`.
- The `author` is a real GitHub account that can answer questions about the plugin.

This is a spot check by one person, not an audit.

## Removal

A plugin is removed from `index.json` (and its bundle from `dist/`) when it is reported as unsafe, when it stops
working on current firmware or Vetro, or when its author asks. Removal does not uninstall it from TVs that already
have it: tell users to switch it off and remove it from the dashboard.
