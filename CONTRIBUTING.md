# Contributing a Shard

Read [what a Shard can and cannot do](docs/what-a-plugin-can-do.md) and the [guide](docs/writing-a-plugin.md) first.

## What a pull request contains

- the source in `plugins/<id>/` (`manifest.json`, the entry file, a short `README.md`); start from `node scripts/new.cjs <id>`;
- `dist/<id>-<version>.vplugin` and `index.json`, generated by `node scripts/build.cjs`. CI runs
  `node scripts/build.cjs --check` and fails when a Shard breaks a rule below that a machine can check, or when they
  are out of date;
- a new `version` for every change to an existing Shard. The hash in `index.json` must always describe a
  published version, so a changed bundle with the same version is refused (CI compares with `main`).

Do not add a signature yourself. The post-merge publisher signs reviewed entries
into the separate `catalog` branch; `main/index.json` remains a build input.

Run `npm ci --ignore-scripts`, `npm test`, `npm run check` and
`npm run test:runtime` before submitting. CI repeats the lifecycle checks on
Node 4.4.7, 12.4.0 and 20; use only ES5 in Shard files. `start()`/`stop()` must release
timers and sockets across restarts. Fake TV command responses in smoke tests are
not proof of working on real hardware: include your model and actual test results.

The required `check` must pass and a code owner must approve an ordinary merge.
Administrators retain their existing explicit bypass; the publishing key must
never be supplied to PR jobs, a Shard test, or a `pull_request_target` workflow.

## What the maintainer checks

- The code is readable: no minified or obfuscated source, no `eval` or `new Function`, no downloaded code.
- It talks only to what the description says. No network calls to hosts the description does not mention, no
  collection of data about the user, the TV or the network.
- `permissions` is as small as possible. A Shard that asks for `exec` must say in its README which commands it
  runs and why; a Shard that does not need `exec` must not ask for it.
- It cleans up in `stop()` (timers, sockets) and keeps its own data in its folder or in `ctx.config`.
- The `author` is a real GitHub account that can answer questions about the Shard.

This is a spot check by one person, not an audit.

## Removal

Remove the source folder from `plugins/` and rebuild `index.json` and `dist/` when a Shard is reported as unsafe,
stops working on current firmware or Vetro, or its author asks. Merge the removal so the publisher removes the
entry from the signed `catalog` branch too. Removal does not uninstall it from TVs that already
have it: tell users to switch it off and remove it from the dashboard.
